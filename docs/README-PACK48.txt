ПОЧЕМУ СТРЕСС ПОКАЗЫВАЛ LEAK 10/10
Ошибка была в самом стресс-тесте. Перед циклами он один раз измеряет
провайдерский адрес («адрес утечки») через Invoke-RestMethod. PowerShell
держит это TCP-соединение к api.ipify.org открытым (keep-alive) и переиспользует
его для всех следующих замеров. Уже установленное соединение продолжает идти
по старому маршруту через Ethernet, сколько бы маршрутов ни появилось потом.
Поэтому измеритель 90 секунд подряд получал 95.27.119.253 при полностью рабочей
цепочке. Ping и tracert в те же секунды шли через цепочку — это видно по логам.

ЧТО ДЕЛАЕТ ПАТЧ 29
1. Каждый замер адреса теперь выполняет curl.exe в отдельном процессе
   с --no-keepalive: соединение создаётся заново и идёт по актуальным маршрутам.
2. Адрес утечки больше никогда не принимается за рабочую цепочку
   (раньше при пустом -Expect он считался успехом).
3. Заодно создаёт заново папку C:\vpn\logs, если её нет
   (из-за её отсутствия awgchain-logs2.bat ответил RESULT=FAIL reason=nologs).

ЧТО ОСТАЛОСЬ ПО КОДУ (пак 49)
В журнале видно настоящую, хоть и короткую, брешь: второе звено отправляет
рукопожатие до того, как его сокет привязан к нижнему звену —
«pinned interface warpam-hop1 not found» и сразу «Sending handshake initiation».
Первое рукопожатие уходит напрямую через Ethernet, то есть сервер второго звена
видит реальный адрес. Через две секунды сокет перепривязывается и дальше всё
идёт через WARP. Исправление: не отправлять пакеты до привязки, а после привязки
переустанавливать сессию. По исходникам апстрима доступ к устройству есть только
в service.go (dev.Up, watcher.Configure), значит правка будет там, не в ожидании.
